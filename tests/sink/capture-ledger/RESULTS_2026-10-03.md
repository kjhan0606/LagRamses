The materialized positive-run namelists were
`/gpfs/kjhan/lagramses_capture_restart_411605/fresh.nml` and
`/gpfs/kjhan/lagramses_capture_restart_411605/restart.nml` (SHA-256 values in
Slurm `411605` log). They requested a full dump only at `tout(1)=0`, supplied
an unreachable second schedule slot, and suppressed periodic/backup dumps.
The sole hydro payload was 5,398,468 bytes and the sole AMR payload was
751,620 bytes. The snapshot info file recorded `unit_l=3.085677581282e21`
cm, `unit_d=1.66e-24` g cm^-3, and `unit_t=3.1556926e13` s, matching the
effective `PHYSICS_PARAMS`. FFTW direct solves completed and no fine-MG
nonconvergence was reported.
This is only an input-to-checkpoint units echo check: those standard-fixture
values imply `G_cgs*rho_unit*t_unit^2=1.1033e-4`, whereas the non-cosmological
sink dynamics use code gravity factor 1. Do not interpret its orbital quantities
as a physically unit-consistent kpc/Myr calculation.

Both fresh and restarted trajectories reported the same coarse-step
diagnostics: at step 2, `mcons=-3.03e-3`, `econs=9.37e-3`, and 15,512 cells
with negative internal energy in the sink-stage diagnostic. The replay is
structurally reproducible, but the synthetic fluid state is **not admitted as
a physics validation**. A physically stable hydro fixture and stronger
conservation gate remain to be designed before claiming an integrated
physical result. The first restart test covers one MPI rank and legacy binary
restart. The two-rank repeat covers MPI lineage and binary restart, but not
HDF5 restart; it likewise does not pass the physical hydro gate. Its step-2
diagnostics were `mcons=-2.11e-3`, `econs=1.21e-2`, and 15,512 negative
internal-energy cells, identical between its fresh and restarted trajectories.

Slurm `411616` was an invalid two-process launch without `--mpi=pmi2`: both
processes identified as `nproc=1` and independently appended `attempt_begin`
to the same ledger. The validator correctly rejected the duplicate fresh
attempt. This was a launcher error, not evidence of a two-rank ledger writer
defect. The tracked runner now uses `--mpi=pmi2` and checks `ncpu` in both
the ledger event and checkpoint info file against the program's rank count.

The HDF5 fresh/restart capture event JSON blocks are identical, but the hydro
trajectory diagnostics are not: step-2 `mcons` changed from `-2.11e-3` to
`-2.28e-3`, and `econs` from `1.21e-2` to `9.06e-3`. Both have 15,512
negative-internal-energy cells. The HDF5 structural capture/restart gate thus
does **not** pass hydro trajectory equivalence or physical conservation. The
solver reports a cold-Poisson restart predictor, but this record does not
establish the cause of the difference. A stable fluid fixture and a separate
diagnosis of the HDF5 hydro discrepancy are still required.
The first HDF5 run, `411641`, completed both solver invocations and validated
the ledger, but its Slurm batch failed because the original evaluator required
identical hydro diagnostics. Re-evaluation explicitly separated structural
capture replay from hydro equivalence. The tracked runner then completed in
`411646` with the structural-only marker and `hydro_replay_identical=false`.
The committed-source repeat `411655` used the clean `411651` binary. Its
negative restart `411656` copied the existing ledger as well as the checkpoint,
then verified that rejecting the missing `COMPLETE` marker changed no ledger
bytes (`de50d154b55aece5717cc3887112a6fdc29e310965e78ea28e703c2dfa05782a`).

The first uniform-gas input (SHA-256
`68af210c299939d35907c125903f6d4531e41c42f46526f7daf746ba2161890d`)
sets `exp_region(1)=100`, so the square region spans the full periodic box;
the original default `exp_region=2` made a spherical region with a low-density
exterior. Its `p_region=1e-3` yields positive sampled internal energy
(`eint_min=1.5e-3`) in both formats. At step 2 the HDF5 fresh run had
`mcons=1.73e-16`, `econs=1.20e-13`; the restarted run had `mcons=0`,
`econs=-3.61e-16`. The legacy fresh/restarted diagnostics both matched the
HDF5 fresh values exactly. These are only **round-off preservation of a
near-static uniform medium**, not a test of conservation in moving gas or
recovery of an evolved state. The full checkpoint is at `nstep_coarse=0`;
step 1's zero conservation error is the initialized baseline, not an
independent measurement. The `411675` and `411676` inputs still had the old
1 Myr time unit. The corrected uniform fixture (SHA-256
`81de9ab0a862b2ddb103c9495baa88acc5768f481ae7d406eb72e79c9cc8c7ce`)
uses `unit_t=3.004298591324383e15 s`, giving
`G_cgs*rho_unit*t_unit^2=0.9999999999999999`; `411686` and `411687` repeated
the limited static round-off result with these units. Neither the static
result nor the new unit choice diagnoses the earlier inhomogeneous HDF5 hydro
divergence.
The first uniform HDF5 run, `411668`, completed both solver invocations but
its batch failed because the old evaluator demanded two `neg_cells` log rows;
positive internal energy emits no such rows. The evaluator now requires
positive sampled `eint_min` when those rows are absent; `411675` and `411676`
both completed with the earlier uniform-hydro numerical marker; later
documentation and the runner name this limited result a static round-off smoke.
Both checkpoint formats here were written at coarse step 0. The current
binary and HDF5 checkpoint writers preserve `mass_tot_0` but do not serialize
the `einit` energy-conservation baseline, so evolved-state restart and its
energy-error continuity remain unverified. This requires a separate
post-step checkpoint fixture and an explicit checkpoint-format treatment;
none of the step-0 smoke results establishes it.

HDF5 build attempts `411629` and `411634` were not accepted: the first found
