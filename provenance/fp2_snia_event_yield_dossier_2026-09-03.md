# F-P2 SNIa event-yield dossier — 2026-09-03

Status: **candidate review only; no event-yield source selected**.

## Decision-relevant findings

Keegans et al. (2023) provide a useful modern composition candidate: the paper
reports 39 SNIa models spanning three progenitor/explosion families and 13
`22Ne` composition points, with complete abundance yields. The associated
Zenodo record supplies decayed isotopic yields and is marked CC BY 4.0. This
is strong provenance for a source-package audit, but it is not by itself a
runtime event contract. The project must still define isotope-to-element
aggregation, decay horizon, returned mass, remnant ownership, event energy,
momentum convention, and the population weighting over the model family.

Seitenzahl et al. (2013) provide an independent three-dimensional
delayed-detonation comparison set with detailed tracer-particle yields. The
models span ignition and central-density choices, so they are useful for
sensitivity or cross-checking. Redistribution terms and a machine-readable
project source package have not been established here; this candidate cannot
become a production input without that closure.

The Heidelberg Supernova Model Archive (HESMA) is registered as a third,
review-only candidate for the missing hydro-side closure. Its archive
description covers integrated isotopic abundances and ejecta information, but
the archive is not itself a unique event model: a concrete model ID, version,
license/checksum, abundance file, and profile convention must be selected and
staged before it can supply event energetics. It is therefore a candidate for
closing the event-energy/profile side, not an approval of any HESMA model.

The HESMA `yysd4-xap92` record has now been staged for review under
`assets/review_only/fp2_snia/hesma_yysd4_xap92`, with its record JSON and the
abundance, isotope, and density archives bound by
`manifests/fp2_snia_hesma_yysd4_review_v1.json`. The machine audit is
`simulation/snrt/data/fp2_snia_hesma_source_audit.json`. It verifies 15
Seitenzahl-model files in each archive, 384 isotope-profile columns, matching
profile row counts with monotonic velocity grids, and all 11 project elements
in the integrated stable element section. It records the source's
approximately 100-s profile epoch and approximately 2-Gyr stable-abundance
convention, but leaves conversion and runtime activation disabled. The
review-only profile estimator compares a documented piecewise
constant-in-velocity shell integral against each model's integrated stable
mass: `n100` is within 5%, while `n300c` differs by about 641% and `n1600c` is
just above the 5% warning threshold. These are source-consistency warnings,
not corrected production values; the estimator cannot replace an authoritative
event-energy/mass record.

The source-specific adapter
`simulation/snrt/tools/adapt_hesma_snia_source.py` now extracts one explicitly
named model into the review-only schema
`snrt-fp2-snia-hesma-source-normalized`. It records the 11-element stable
composition vector, source-member checksums, and profile metadata while
retaining the source's decay convention. It deliberately emits no converter
input and leaves returned mass, remnant, energy, signed momentum, decay
horizon, and population weight unset. Thus `n100` is an auditable extraction
fixture, not a selected production model; profile warnings such as those for
`n300c` remain visible in the extracted document.  The adapter and admission
sidecar reject every warning-bearing model, not only models classified as
quarantine anomalies.

The checksum and admission record is
`simulation/snrt/config/fp2_snia_event_source_approval_sidecar_v1.json`,
audited by `simulation/snrt/tools/audit_fp2_snia_event_source_admission.py`.
It binds the review extraction to the HESMA manifest and source audit while
keeping every physical event field and the approval id unset.  Its
`required_for_promotion` mirror is checked against the canonical promotion
field list, and artifact paths are required to be repository-relative.

The all-model review matrix is
`simulation/snrt/data/fp2_snia_hesma_model_comparison.json`, generated by
`simulation/snrt/tools/build_hesma_snia_model_comparison.py`. It contains all
15 staged models under one comparison rule, but deliberately has no automatic
ranking, population mixture, selected model, or canonical rows. The F-P2
contract audit requires this unselected state and verifies that its package
checksum matches the HESMA source audit.

The separate profile-estimator comparison
`simulation/snrt/data/fp2_snia_hesma_profile_estimator_comparison.json`
tests the existing zero-inner-edge rule against a half-bin extrapolation at
both ends. For `n100`, the mass estimate changes only from 1.45324 to 1.45311
M☉; for `n300c`, it remains about 10.37 M☉ versus an integrated stable mass
of about 1.40 M☉. Therefore the large `n300c` discrepancy is not a shell-edge
artifact and remains an unresolved source-physics warning.

## Candidate disposition

The machine-readable comparison is in
`simulation/snrt/config/fp2_snia_event_yield_candidate_matrix_v1.json`.
The three supplementary files used for review are staged under
`assets/review_only/fp2_snia/keegans2023` and bound by
`manifests/fp2_snia_keegans2023_review_v1.json`; their integrity result is
recorded in `simulation/snrt/data/fp2_snia_event_yield_asset_audit.json`.
The source-format audit is recorded in
`simulation/snrt/data/fp2_snia_keegans_format_audit.json`; it finds 70 isotope
rows and 13 `22Ne` columns per file, but H, He, C, and N are absent from the
staged package and therefore blocks direct 11-element closure. The audit now
distinguishes absence from an explicit zero: these four project elements have
no isotope rows in the staged tables, and none is classified as an
explicit-zero-only element. This is not evidence that their physical ejecta
are zero. In particular, the paper describes the T1.4 fuel as otherwise
composed of C and O while using `22Ne` as the neutron-excess/metallicity proxy;
the absence of C from the staged row list therefore cannot be promoted to a
zero C ejecta assumption. The conversion policy is consequently fail-closed:
an absent element must not be silently filled with zero.

- **Leading composition candidate:** Keegans et al. 2023, not approved.
- **Leading profile/energetics candidate:** HESMA model archive, no model ID selected.
- **Independent comparison:** Seitenzahl et al. 2013, not approved.
- **Production source:** none.
- **Runtime activation:** disabled.

The DTD candidate matrix remains separate. A DTD choice does not select an
event-yield model, and an event-yield table does not determine the event-rate
normalization.

## Required conversion and approval inputs

Before F-P2 can activate, the selected package must be downloaded into the
manifest-scoped asset area, hashed, and converted deterministically. The
conversion must state isotope decay epoch/horizon, map the source isotopes to
the project element set, close total ejecta against returned mass, and keep
net-yield diagnostics distinct from actual ejecta. The event record must also
pin energy and signed momentum semantics and explicitly declare that no
terminal remnant is returned by a normal SNIa event. A named approval id must
bind the source, conversion, population weighting, and all resulting checksums.
