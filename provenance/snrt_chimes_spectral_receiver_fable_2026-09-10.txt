Verdict first: **proceed with the plan as the next increment, after folding three executability fixes into its text.** The physics is consistent with the existing absorber, bridge and FS2010 closure. Nothing in it is an artificial gate. The plan file could not be written because the Write tool is disabled in this session, so the audit is below.

**Q-GOAL. Does it deliver the missing runtime coupling?** Yes for the operator, no for runtime, and the plan says so honestly. Today the bank only returns rate moments; `snrt_chimes_band_moments` is explicitly "NOT finite-inventory captures". The plan adds the missing cell-local, species-evolving, finite-inventory absorber on the real CHIMES157 state. Runtime coupling stays blocked by two existing guards, in `snrt_spectral_contract.f90` at line 117 and in the driver at line 642, and the plan keeps them. That is right: the bank has no Lyman-Werner H2/CO dissociation, no grain competition, and no checkpoint identity.

One working-tree fact the plan omits. The Makefile already builds `snrt_chimes_photo.o` from a source file that does not exist, and the new internal header defining a shared bank struct is not included by `snrt_chimes_spectrum.cpp`, which still has its own private struct. CHIMES=1 targets cannot build right now.

**Q-LEAN.** Lean and correct: one surviving fraction per node rather than per node and direction, CVODE reuse, no new test framework, unchanged guards. Excess worth trimming:

- **FS sample caching** at every node/shell energy is about 0.5 GB globally, or as costly as the right-hand side if done per cell. Cache only the energy-grid index and weight per shell/node pair and interpolate in the ionized fraction at run time.
- **Photon fractions as ODE unknowns** are unnecessary. With column integrals of each absorber density, the surviving fraction at a node is an exact exponential of those integrals. The state drops from about 1300 to about 300 unknowns, photon positivity holds by construction, and the removed-photon budget becomes exact. It also makes the dense linear solver CHIMES already uses adequate. Unpreconditioned SPGMR on a stiff optically thick cell is a convergence risk, not a leanness win.
- **Duplicate tests.** Directional hardening, threaded bitwise equality and invalid-N/E rejection already exist in the smoke. Only finite depletion, dt halving, the Auger reservoir budget, zero identity and rollback are new.

**Feasibility and conservation, verified against source.** The common per-node attenuation across directions matches how `absorb_cell` already works. The energy ledger, photon energy equals primary electron energy plus shell binding, mirrors the grey bridge's rule of inventing no cascade energy. H- and H2 rows carry one released electron and conserve charge and nuclei by construction, and the loader already validates the mapping. SUNDIALS 5.8.0 is installed and linked with both dense and SPGMR solvers, so CVODE code must target the 5.x API without a context object.

Mandatory before implementation, all executability rather than new physics:

1. **Build wiring.** Create the photo source file and make the spectrum file use the shared bank struct. Casting the opaque handle to a different type in a second translation unit is an aliasing bug even when the layout matches.
2. **Acceptance tolerances.** "Reject negative species and photons, no clipping" needs a stated tolerance tied to the CVODE tolerances, or solver-level constraints. The photon-versus-capture budget must be checked at relative-tolerance level, not the FP32 ulp level used by the existing absorber, or nearly every cell will reject.
3. **H2 gating.** The bank ionizes H2 at any temperature, while CHIMES freezes molecules above its molecular temperature limit. State whether the H2 row follows the same criterion, or the following CHIMES step strands H2+.

Optional suggestions, not gates: split the reservoir into chemical binding and unresolved Auger or fluorescence energy for later comparison with recombination cooling; deliver photoheating as a rate through the existing hybrid cooling hook so heating and cooling share one thermal integration; sum cross sections per reactant for the attenuation term to cut right-hand-side cost.

**Does the later split need a different design?** No. Photo operator first, then the existing charged CHIMES cell call with zero photons, which legitimately zeroes every photo channel. This is the same first-order split as the native H/He path. Two interface facts apply: the 157-species state lives in Fortran cell arrays, not in the C++ transport, so the operator is called from the driver's chemistry loop with per-direction N/E; and zero photons also zero molecular dissociation and grain photoelectric heating, which is exactly why the guard stays.
