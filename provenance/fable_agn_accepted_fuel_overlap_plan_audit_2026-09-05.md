## Prioritized findings

**1. (Blocking — amend A) Replace the "cumulative receipt + consumed-energy cursor keyed by `idsink`" with a slot-carried pending reservoir.**
`merge_sink` remaps `msink/dMsmbh/Esave/idsink/spin` (1633-1635, 1692-1701) but **not** `dMBH_coarse`/`dMEd_coarse`. Under legacy AGN that is harmless (reset every coarse step at 6389, before `create_sink→merge_sink` at `amr_step` 424→477). Under live SNRT there is no reset, so after any merger the driver's idsink-keyed `accounted_inflow` is compared against a wrongly-permuted `dMBH_coarse` — the existing design already violates the plan's "preserve records across array reorder", and a second idsink-keyed energy cursor would inherit it. Minimal correct design:
- one extra column in `sink_thread` (`accrete_bondi` 4591-4596; `grow_bondi` 3953, 4131-4145, MPI pack 4151-4179, apply 4182-4190) accumulating `ε_event·dm_gross` (code mass; ε from 4477-4486, `dm_gross` = `dmsink` before 4487);
- a `pm_commons` per-sink pending array: zero for new sinks (`init_sink`, `kjhan_make_sink` 1097-1109), **summed into `igrp`** in `merge_sink` next to 1633-1635 and copied at 1692-1701 (this *is* the "explicit transfer via existing merger mapping"), zeroed in `AGN_feedback` at 6389 so legacy runs stay bounded;
- driver: emit `pending·scale_m·c²`, zero it only when `source_ok` (747-754); failure leaves it pending → automatic retry. Delete `accounted_ids/accounted_inflow/retained_seen/retained_initialized` (238-240, 598-634) and the regression/retained-bound skips (663-707). Since serial fresh start is enforced (286), this reservoir is exactly as safe as `dMsmbh`, and there is no need for any "unexpected identity transition" logic beyond the existing 579-590 validity check.

**2. (Blocking — amend B) Layout must be selected/validated once in `grow_bondi`, not in `AGN_feedback`.** `agn_scalar_map` is only invoked from `AGN_feedback` 6194-6216, which never runs under SNRT (6184-6189). Factor those lines into one small shared routine used by both callers; `clean_stop` before the accretion loop. In `accrete_bondi`, replace the `imetal`-only `z` handling with `uold(indp,scalar_fields) *= (1 - dm_gross/(d_old·vol_loc))` inside the existing lock. Do **not** call `agn_withdraw_cell` — it imposes the 25 % cap (178) and the cold-loading energy rule (182), which the plan itself forbids transplanting.

**3. (Simplify C — non-blocking) No donor-payload recording, sparse lookup, or "bounded receiver snapshot" fallback.** The sparse donor map already exists: `ind_blast(iAGN)` (owner-only, else −1) and global `mAGN(iAGN)` (0 for non-loaded events, incl. fallback events which also loaded). In `AGN_blast` 7060-7076, before the AGN while-loop, set `d_ref = uold(cell,1)` and add `mAGN(iAGN)/vol_loc` for every `ind_blast(iAGN)==ind_cell(i)` in the same neighbor-bin list; use `d_ref` at 7089 and 7106. Premise verified: between `average_AGN`'s AMR pass (6621-6728) and `AGN_blast`'s loop the only `uold` mutation is sequential loading (6774-6780); within a cell, only that cell's own deposits (7110). Jet thermal share (7098) is volume-weighted and unaffected, as the plan states. Drop the fallback clause.

**4. (Non-blocking) Photon budget energy entry.** Add `snrt_agn_photon_budget_energy(E_erg, dt_s, fraction, mean_eV, L, N)`; the existing mass entry (`snrt_agn_source` 19-50) delegates. With ε carried by the receipt, `snrt_agn_resolve_efficiency` (driver 657-660, 692-698) must not remain a second source gate — keep it for status/mode reporting only, or drop it.

**5. (Non-blocking) Tests are proportionate; keep them at the existing runner** (`simulation/snrt/tests/run_fp15_agn_efficiency.sh`). Extend `snrt_agn_source_smoke.f90` (energy entry ≡ mass entry × ε; zero → zero) and `agn_feedback_deposition_smoke.f90` (overlap case with `d_ref` recovery: two thermal + one jet sharing a donor, Σ requested = EAGN, reversed order closes). For the receipt arithmetic, a pure helper is acceptable only if it *replaces* the inline gross/retained computation in `accrete_bondi`; otherwise caller-compile inspection suffices. No driver-level harness, no Python.

**6. Scope notes.** Keep `dMBH_coarse/dMEd_coarse` intact (legacy `X_radio` at 6304-6305, `SNRT_LEDGER_DIAGNOSTIC`). State explicitly that the driver's retained-bound/regression skips are removed, not kept alongside receipts. Accretion's non-scaling of `nener`/reserved fields is pre-existing and out of scope — no new stop.

## Overinstrumentation assessment
- Over-built: A's dual idsink-keyed cursors (net code *increase* where a reservoir gives a net decrease); C's recorded payload + lookup + conditional snapshot pass. Both replaced above by ~20 lines each.
- "Validate finite mass, units and efficiency before mutation" in the accretion inner loop must not become a new `clean_stop` in production accretion; the fail-closed boundary already exists at `snrt_agn_source` 31-43.
- Cadence (one evidence record, one Opus end review, Fable plan review) matches the entrainment bundle; no new gate.

## Is the bounded precursor justified?
Yes. A corrects an actual energy-source error in the production RT path (photons funded by floor-clipped gas, post-spin ε, and an unbounded cumulative difference); B fixes composition non-conservation on every accretion event, which element-resolved chemistry and any later dust model depend on; C closes the mechanical budget where events overlap. All three are source changes, not instruments. The physical partition (gross vs retained, MAD spin energy, SED luminosity basis) is a model decision, and the plan is right to refuse to smuggle it in — with the reservoir design the follow-on inherits a per-event `ε·dm_gross` receipt and `dMsmbh`, which is sufficient input for that decision without re-plumbing.
